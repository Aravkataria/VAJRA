Three model tiers, none grading its own work.

Strict separation between the model that finds a problem, the model that fixes it, and the model that tries to break the fix.

01 Security Analyst — diagnoses only
02 Decision Engine — routes the fix
03 Repair Model — proposes a patch
04 Verification — tries to break it

Build on evidence, not a model's confidence

The Security Analyst only explains vulnerabilities and never writes patches. The Repair model proposes a minimal fix and never validates itself. The Verification model is strictly adversarial — its only job is to try to break the patch before it ever reaches your code.

Native Rust core, zero-cost fast path

A multithreaded scanner built on Rayon parses thousands of files per second across every CPU core. Known-safe fixes apply in under 5ms with zero inference cost — the reasoning model only gets involved when the fix genuinely needs judgment.

Deterministic fast path

Context-free fixes like yaml.load → yaml.safe_load, verified in <5ms.

Local reasoning path

Complex, multi-line logic routed to a local Ollama model — nothing leaves your machine.

FAQ.

Looking for answers? Everything you need to know about VAJRA.

VAJRA scans codebases for concrete vulnerability sinks (command injection, eval/exec, SQL injection, insecure deserialization, path traversal, hardcoded credentials), synthesizes minimal surgical AST patches, and independently executes a 6-stage verification matrix to prove every patch before code is applied.
To prevent AI hallucinations, VAJRA enforces total separation: Tier 1 (Security Analyst) exclusively diagnoses vulnerabilities and never writes code; Tier 2 (AI Repairer) synthesizes minimal AST repairs and never validates itself; Tier 3 (Verifier) is strictly adversarial and attempts to exploit and break the proposed patch.
Every candidate patch must score a 6/6 PASS: (1) Syntax AST integrity, (2) Static sink elimination re-scan, (3) Dynamic exploit sentinel PoC execution, (4) Baseline regression test run, (5) Boundary input fuzzing, and (6) Patch mutation invariant test (requiring 100% mutant kill score). If any stage fails, the patch is rejected atomically.
VAJRA calculates a composite risk score (0.0–100.0) weighting Severity (35%), Exploitability (25%), Call-Graph Reachability (20%), Git Recency (10%), and Complexity (10%). Vulnerabilities are classified into SYSTEM_WIDE, SERVICE, or ISOLATED blast radius tiers to prioritize critical security flaws.
Rather than rewriting whole files, VAJRA calculates line delta (ΔLOC), AST token distance, and cyclomatic complexity changes (ΔCC). It strictly enforces an Invasiveness Score under 35%, ensuring fixes are surgical, safe, and maintainable.
Verified 6-stage fixes are automatically indexed into a persistent local knowledge graph (.vajra/knowledge_graph.json). When identical sinks appear in future scans, VAJRA retrieves the proven fix instantly (0ms fast path) and can export training datasets for offline model fine-tuning.
